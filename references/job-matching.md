# 岗位匹配（job-matching.md）

两个使用场景：①对练/材料攻防前的岗位建模（若用户给了目标公司，先走 Stage 0 企业匹配分析，见 references/company-intel.md——本文件的 JD 解析负责「岗位画像」，company-intel 负责「企业情报 + gap 弥补」，两库隔离按 R8）（JD → P0/P1/P2 考点，喂给选题公式与 V2 判定）；②用户直接要求「评估我与这个 JD 的差距」时单独产出差距清单。

## 双向解析

### JD → 岗位画像（正向）
从 JD 文本提取：
1. **P0 垂直技能**（3 项以内）：出现 ≥2 次或位于「任职要求」前两条的技术。→ G3 的考点来源，也是 V2「基础空心」的判定基准。
2. **P0 通用基础**：职级对应的必会项（初级=语言/数据结构；中级=系统设计/存储；高级=架构权衡/容量规划）。
3. **隐性信号**：加班措辞、团队规模、业务阶段（0→1 还是 1→10）——影响 J/N 的考察侧重。

### 简历 → 候选人画像（反向）
从简历提取：
1. **强声称清单**：所有「精通/深入理解/独立设计/主导」词汇 + 对应技术点。→ 每条强声称必须至少被一轮选题命中（暴露概率因子）。
2. **量化成果**：所有数字（QPS、百分比、规模）。→ G2/I 的核对目标，无来源的数字是 V1 观察点。
3. **经历断档/跨跳**：时间线检查点，I 的交叉验证素材。

## 差距清单模板（P0/P1/P2）

```
【差距清单｜岗位 X vs 候选人 Y】
P0 致命差距（不补无法过面）：
  1. [差距] 证据：JD「___」 vs 简历/面试「___」
     学习路径：3 步以内，每步可验证
P1 明显短板（影响定级）：
  ...
P2 可快速提升（面试中可绕过）：
  ...
匹配度：P0 命中 _/_，P1 命中 _/_
```

分级规则：JD 必须项且候选人无任何信号 = P0；JD 必须项有信号但面试验证 ≤4 分 = P0；JD 加分项无信号 = P1；表达/材料类问题 = P2。

## 面试策略模板（输出给候选人的备战建议）

对练/材料攻防结束后，与终审报告一同输出：
1. 该岗位的面试官会重点攻击的 3 个点（来自 P0 清单 × 强声称清单的交集）。
2. 候选人现有材料的改法：哪些强声称该降级为「熟悉」，哪些数字需要补来源。
3. 3 个必须准备的大白话解释（自己简历上最贵的技术词）。

## 与其他文件的接口

- P0 清单 → selection-rules.md（暴露概率/问倒概率判据）+ scoring-veto.md（V2 判定基准）。
- 权重表 → rules-config.yaml `dimension_weights`（按岗位族覆盖默认值，如 AI 研发岗 G3=12%、L=20%）。
