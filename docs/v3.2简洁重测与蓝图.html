一、认错与修改

漏洞：output-spec 只限产物（600 字），给自己留了「对话不受限」的豁免——于是每条回复三四百字带大表格，你被迫反复说「简化」。

v3.2 已写入 output-spec.md §9（对话输出纪律）：① 回复 ≤5 句或 ≤150 字，首句给结论；② 一次只给一个主链接；③ 对话表格 ≤4 行 ×3 列；④ 写完数句数，超了就删；⑤ 用户明确要详述时不设上限，仍结论先行。

四、Agent 开发 vs Skill 设计：区别与联系

维度Skill（本 skill 这类）Agent 开发（如 ZCode、工作流系统）
本质提示词工程制品：markdown 指令包 + 知识文件，教模型「怎么做」软件系统：感知→决策→行动→记忆的常驻循环，自动执行
状态无状态——靠每轮重述状态表（R5）对抗漂移有状态——会话、数据库、检查点原生持久
可靠性指令遵循 + 人审 + 脚本验收兜底工程保障：单元测试、重试、监控、回滚
演进改文本即生效，零部署改代码→构建→部署，版本管理
关系Skill 是 Agent 的技能注入，Agent 是 Skill 的执行引擎。本 skill 的 R7 条件增强层就是桥：运行时支持子 Agent 派发时，单 agent 指令包自动升级为多 agent 编排（盲评独立子 agent）。本会话即实例：tech-interview-skill 跑在 ZCode agent 上。
一句话：Skill 回答「怎么做才对」（程序性知识），Agent 回答「自动把它做完」（自主执行）；Skill 的上限被 Agent 运行时能力封顶，Agent 的下限被 Skill 质量托底。
