# 输出交付规范 v2（output-spec.md）

本 Skill 一切**阶段产出物**（企业情报卡 / 差距与弥补报告 / 预演手册 / 终审报告 / 综合备战报告 / 漏洞清单 / 行业下钻卡）的输出纪律。对练每轮输出仍走 SKILL.md §2 纯文本固定标签（R5 结构稳定性），本规范不作用于对话过程。

设计哲学一句话：**写给人看，交给机器查**——所有输出用大白话写结论；所有验收（字数、结构、来源、链接）交给脚本复查。

## 1. 统一五段式骨架（四类产出物同构适配，只换语义不自创结构）

| 段 | 填什么 | 上限 |
|---|---|---|
| S1 一句话结论 | 判定/画像 + 关键数字 + 信心度（高/中/低） | ≤50 字，1 行 |
| S2 原理核心 | 1 张机理图（必须）+ ≤3 个技术点，每点三句式：①大白话定义 ≤25 字 ②原理 ≤35 字 ③业务怎么用 ≤30 字（须点名目标公司场景） | 1 图；每点 ≤90 字 |
| S3 可执行步骤 | 动作 + 可观察验收（复测≥7 分 / 60 秒讲完 / 追问 2 层不穿帮 / 产出可查证物） | ≤5 步；动作 ≤30 字 + 验收 1 行 |
| S4 检查清单 | checkbox 拿来即勾 | ≤6 项 × ≤15 字 |
| S5 风险与边界 | 触发 → 后果 → 兜底 | ≤3 条 × ≤30 字 |

全文上限：情报卡 600 字 + 1 图；差距报告 800 字 + 1 图；预演手册 250 字/题；终审报告 900 字 + 1 图；行业下钻卡 700 字 + 1 图；简历改进报告 800 字 + 对照表（逐条：原句→改后→理由→[P-xx]，另附改进版全文与命中度对比）。**超限删内容，不折行不加滚动**——「分析了」不算交付。

## 2. 说人话五律

1. 结论先行：打开首屏必须能读完结论与全部行动项；
2. 术语第一次出现必须带括号解释（例：「前馈（一次推理直接出结果，不用反复优化）」）；
3. 每个核心概念配一句大白话版——大白话讲不清的概念不许只写术语；
4. **公式明确**：凡涉及评分、加权、优先级、命中率、阈值等任何计算，必须写出明确数学公式（符号式，禁用纯文字描述），公式下一行用人话解释每个变量的含义与取值范围。示例：
   ```
   匹配度(%) = (方向对口×40% + 证据强度×35% + 短板可控×25%) × 20
   → 三项各 1–5 分打分（依据随附），×20 换算百分制；改任何一项分数可重算。
   ```
   违规示例：「综合考虑各方面因素后给出较高评分」——没有公式 = 没有评分。
5. **表格清晰**：一表一主题；表头完整（每列有名字，宽列在表头声明）；一格一句话（不嵌套表格、不塞多个事实）；长表跨节必须重复表头；数字右对齐、文字左对齐。

## 3. 来源四色标记（无标记论断不渲染）

- 〔简历〕= 候选人简历原文数字（[P-xx]）｜〔官方〕= 公司官网/JD/团队主页/论文（[C-xx]/[I-xx]）｜〔实测〕= 本会话真实测量值｜〔推断〕= 基于证据的分析判断（须附依据）。
- 无上述标记的论断在生成时即判无效，不进正文；R3/R9 的渲染层落地。

## 4. 图示与动图规范

- 载体：单文件 HTML，`<style>`/`<svg>` 全内联；禁外链、禁 CDN、禁 JS。
- 图形：矢量 SVG 优先（viewBox 自适应）；位图仅限简历截图等原始证据，缩略展示。
- **动图禁 GIF，用 SMIL/CSS 动画**：①帧由代码定义，可与论点编号精确同步；②无限缩放不失真；③体积小约一个量级；④纯文本可维护、离线可用。
- 图文对应：动画元素 id = 论点号；动画循环 ≤8s；**首帧即完整静态图**（截图/降级不丢信息）；`prefers-reduced-motion` 时退化为静态终态。
- 坐标数值须经计算（脚本算好再写进图），不许目测。

## 5. 机器验收五查（写完必须跑，agent 自报数字不可信）

1. **结构查**：标签闭合、锚点有效（HTML parser 脚本）；
2. **字数查**：正文字数 ≤ 上限（含图内文字，去空白计数）——agent 曾自报 598 实测 1078，一律脚本复验；
3. **来源查**：无标记论断 = 0；页首显示计数行；
4. **内容查**：关键内容关键词全在（断言列表逐一 assert）；
5. **截图查（重要交付物适用）**：浏览器实际打开页面截图存证（本地 HTTP 服务 + 浏览器截图，PNG 存 shots/ 目录，验收文档嵌 JPEG 压缩版）——截图经程序化验证（尺寸/颜色数/非白占比）确认非空白渲染。

## 6. 子 Agent 调用四规矩（实测翻车教训，全部有据）

1. **搜索类任务必须限次数**（WebSearch ≤3 次/批）——不限则外呼等待卡死（实测 600s 超时零产出；加配额后 133s 成稿）；
2. **子 Agent 自报的数字不可信，一律主会话脚本复验**；
3. **小任务放行、大任务加护栏**：盲评类（≈1 万 tokens）直接派；深度分析类（6 万 tokens 起）必须带配额与时间盒；
4. **失败重试必须换本质方案**（换执行者 / 换方法 / 加约束），不准原样重跑。

## 7. 与硬规则的兼容映射

R3→评分与否决信号渲染「逐字引用」块，无引用该行不渲染；R4→S2 第①句即大白话档；R6→漏洞清单每条挂「材料原话」引用块；R8→HTML 产物按域分目录，含 [P-xx] 的文件页脚标注「个人库·敏感·禁外发」；R9→预演答案每句挂 [P-xx] 角标，页内显示「无标句 = 0」计数；R1/R2/R5/R7 只作用于对话过程，不受本规范影响。

## 8. 文件命名与存放

`{YYYYMMDD}-{产出物}-{company|candidate}.html`，按 R8 分目录：企业库产物 → `company-intel/`；个人库产物 → `candidate-materials/`。

## 9. 对话输出纪律（v3.2 新增——本节作用于对话过程，堵住「只管产出物」的漏洞）

此前规范只约束产出物，导致对话回复冗长——用户反复反馈「太复杂」。自本节起，对话输出与产出物同等受限：

1. **回复 ≤5 句或 ≤150 字**：第一句必须给结论；证据与细节写进文档，对话里只留链接。
2. **一次只给一个主链接**：多文档时指向最相关的一个，其余留在文档内互链。
3. **对话表格 ≤4 行 ×3 列**；禁止在对话里罗列过程步骤（过程属于文档）。
4. **自检**：写完数句数，超了就删；删不动的内容说明它该进文档，不该进对话。
5. **适用范围**：普通回复与汇报；用户明确要求展开详述（如「详细说明」）时不设上限，但结构仍需结论先行。
