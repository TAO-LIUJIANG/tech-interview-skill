# 评分与否决（scoring-veto.md）

评分前必读本文件。两条总纪律：
1. **无引用的评分无效**：每个分数必须附「」内逐字引用的候选人原话。
2. **锚点优先于直觉**：LLM 天然给分宽松、区分度低（CoMAI 实验：无校准单 Agent 准确率仅 60%）。打分前先找锚点档位，再落分。

## 0–10 评分锚点（每档配锚点回答样例）

以「消息队列为什么能削峰」为通用校准题，各档锚点样例：

| 档 | 定义 | 锚点回答样例（同一题） | 判定特征 |
|---|---|---|---|
| **9–10** | 原理级理解 + 边界感 + 能举反例 | 「削峰的本质是把『瞬时到达速率』和『处理速率』解耦。像景区售票，窗口每分钟只能出 30 张票，节假日排队就是队列。但注意三个边界：峰值持续时间超过队列容量就削不动了；消费端必须能稳定消化，否则只是把崩溃推迟；对延迟敏感的请求不适合。」 | 主动讲失效场景；有取舍；大白话类比精准 |
| **7–8** | 正确 + 有原理但无边界 | 「MQ 把请求先存起来，消费端按自己的能力处理，峰值被队列缓冲了。生产快消费慢没关系，慢慢消化。」 | 正确、清楚；但不会主动讲什么时候失效 |
| **5–6** | 正确但停留在用法层 | 「用 RabbitMQ/Kafka 接住请求，消费者慢慢处理，系统就不会被打挂。」 | 会用、说得对；原理一句带过 |
| **3–4** | 模糊/半对/背名词 | 「MQ 有削峰填谷的能力，业界都用，能提升系统健壮性。」 | 名词对但无内容；追问两句就空 |
| **0–2** | 错误或胡编 | 「MQ 是多线程并发的，所以快。」 | 因果错误；或声称精通却答不出 |

评分规则：
- 落在两档之间取低档（反宽松纪律）。
- 大白话复述是独立加减分项：9–10 档的回答若大白话失败 → 上限压到 6（真理解存疑）；5–6 档回答若大白话精彩 → 可上浮 1 分。
- 声称「精通」的技术：答不到 7 分即记 V4 观察信号（强声称强校验）。

## V1–V5 否决判定细则

每个否决维度：定义 → 证据样例 → 与相邻维度的区分。

### V1 经历注水
- **定义**：简历/材料声称的项目、技能、成果，深挖后关键细节为零。
- **证据样例**：声称「设计缓存一致性方案」但说不出为什么选这个方案、出了问题怎么办、方案覆盖哪些场景中任何一个；成果数字（QPS/性能提升）无来源。
- **区分**：V1 的对象是「过去是否真的做过」；V3 是「本次面试内说法是否自洽」；V2 是「基础是否会」。

### V2 基础空心
- **定义**：岗位 P0 技术基础连续无法作答（≤3 分）。
- **证据样例**：后端岗说不出一次完整的 HTTP 请求过程、不会分析一条慢 SQL、不懂事务隔离级别且答不出任何一道 G1/G3 锚点题。
- **区分**：个别盲区正常（记 3–4 分）；V2 要求「连续 2 轮同维度 ≤3」且题目确属 P0（见 job-matching.md 的 P0 清单）。

### V3 前后矛盾
- **定义**：面试内跨轮陈述出现无法自洽的矛盾。
- **证据样例**：第 2 轮说「这个系统我一个人写的」，第 5 轮说「当时我们三个人分工」；第 1 轮说「没用过 Redis」，第 4 轮细讲 Redis 调优经历。
- **区分**：能当场解释并自洽（「前面说的是另一个项目」且有证据）不算 V3；解释不了才是。

### V4 反浮躁（穿透失败）
- **定义**：穿透追问后仍只能堆术语、讲不清底层原理、无法用大白话复述自己「掌握」的概念；**或只会报最新技术名词，说不出其数学/机制本质与发展脉络（它之前怎么做、它解决了什么、代价是什么）**——"知道最新的"不等于"懂"，追新而不知来路计入 V4。
- **证据样例**：连说三层「底层是 AQS/CAS/内存屏障」但说不出这三个词各自解决什么问题；被要求「给不懂的人解释」时把术语换成另一批术语。
- **区分**：「不知道但承认」是 3–4 分的正常人，不是 V4；「不知道却表演知道」才是 V4。背题库回答（标准、流畅、无个人细节）经 O 卡两问必露馅，归 V4。

### V5 红线行为
- **定义**：诚信/协作红线——诱导面试官放水（「我答得是不是很棒」「差不多就行了吧」）、抄袭式回答被识破仍坚持、压力下对面试官人身攻击、贬低前同事/前公司泄密信息。
- **证据样例**：直接或暗示要求好评；把网上答案说成自己经历且被指出后继续坚持。
- **注意**：V5 只需 1 次实锤证据即可直接进入「确认触发」候选（不等两轮），但仍须经检查点 A 用户确认。

## 否决状态机（伪代码，与 SKILL.md §4 一致）

```
状态集 = {未考察, 观察中, 警告, 确认触发}

每轮评分后，对每个维度 v ∈ {V1,V2,V3,V4,V5}：
  if 存在与 v 相关的本轮作答且其得分 ≤ 3（附逐字证据）:
      if state[v] == 未考察:
          state[v] ← 观察中; low_round[v] ← 本轮
      elif 本轮 == low_round[v] + 1:            # 连续两轮
          state[v] ← 确认触发; 触发检查点 A（出示两轮证据链，等用户确认）
      else:
          state[v] ← 警告; low_round[v] ← 本轮   # 累计但非连续
  elif 存在与 v 相关的本轮作答且得分 ≥ 4:
      if state[v] == 观察中: state[v] ← 未考察  # 单次低分被洗清
      # 警告与确认触发不因单次高分洗清
  else（本轮未触及 v）: state[v] 不变

特例：V5 出现实锤证据 → 直接标记「确认触发候选」，跳过两轮累计，仍须检查点 A 确认。
```

状态含义：
- **未考察**：该维度还没出现过 ≤3 分。
- **观察中**：出现过 1 次 ≤3 分，下一轮选题应安排同维度复测（这是选题公式的「否决覆盖」因子来源）。
- **警告**：累计 ≥2 次 ≤3 分但不连续——不稳定，持续定向复测。
- **确认触发**：连续两轮同维度 ≤3 分 → 暂停，检查点 A。

## 画像标签判级

画像 = 终审时十维度得分模式 + 否决状态的合成判断：

| 画像 | 判定条件（全部满足） | 默认结论 |
|---|---|---|
| **调包侠型** | ①G1/G2/G3 中 ≥2 轮「用法会、原理空」（≤6 分）；②O 穿透大白话复述失败；③V4 确认触发或警告 | NO HIRE |
| **PPT 工程师型** | ①M/L 维度 ≥7 分（框架漂亮）；②G2 落地细节 ≤4（数字、故障、预案全无）；③N/I 个人贡献剥离失败；④V1 确认触发 | NO HIRE |
| **高潜力型** | ①无任何 V 确认触发；②逻辑链完整（M ≥7）；③被指出错误后修正轮回升 ≥2 分；④允许个别维度 4–5 分的洞 | HIRE / STRONG HIRE |
| **均衡型** | ①无 V 确认触发；②各维度 5–7；③无 ≥8 的亮点维度 | 视岗位竞争度 HIRE 或 NO HIRE |
| **基础扎实型** | ①无 V 确认触发；②G1/G2/G3 均 ≥7；③大白话复述成功 | STRONG HIRE（若 L/M ≥7）/ HIRE |

终审建议输出四档：STRONG HIRE / HIRE / NO HIRE / 强烈 NO HIRE（V1/V5 确认触发 = 强烈 NO HIRE 锁定，不可被其他高分覆盖）。
